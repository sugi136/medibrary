## 1. 프로젝트 개요

서비스명 : 메디브러리(Medibrary)

약 이름/모양/색깔로 의약품을 검색하면 효능·용법·주의사항과 **국내(e약은요) + 해외(openFDA) 부작용 사례**, 낱알 이미지를 보여주고, 자주 찾는 약은 즐겨찾기로 관리합니다. 또한 즐겨찾기한 약들 사이의 **병용금기(DUR)**를 자동으로 체크하고, **약 상세 화면에서도 현재 보고 있는 약과 함께 복용하면 안 되는 약(병용금기/주의 의약품)을 별도 탭에서 조회**할 수 있는 서비스입니다.

## 2. 기술 스택

| 영역 | 스택 |

## 3. 데이터베이스 스키마

`02_ERD.dbml`과 동일한 구조의 MySQL DDL입니다. 그대로 실행해 초기 스키마를 만드세요.

```sql
CREATE TABLE users (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE drugs (
  id VARCHAR(20) PRIMARY KEY,              -- 식약처 품목기준코드
  name VARCHAR(200) NOT NULL,
  shape VARCHAR(50),
  color VARCHAR(50),
  mark_front VARCHAR(100),
  mark_back VARCHAR(100),
  ingredient_en VARCHAR(200),              -- openFDA 매핑용 영문 주성분명
  image_url VARCHAR(500),
  efficacy TEXT,
  usage_info TEXT,
  caution TEXT,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE favorites (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  drug_id VARCHAR(20) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_user_drug (user_id, drug_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (drug_id) REFERENCES drugs(id) ON DELETE CASCADE
);

CREATE TABLE dur_pairs (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  drug_id_a VARCHAR(20) NOT NULL,
  drug_id_b VARCHAR(20) NOT NULL,
  reason VARCHAR(300),
  severity VARCHAR(20),
  FOREIGN KEY (drug_id_a) REFERENCES drugs(id),
  FOREIGN KEY (drug_id_b) REFERENCES drugs(id)
);

CREATE TABLE side_effect_cache (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  drug_id VARCHAR(20) NOT NULL,
  source VARCHAR(20) NOT NULL,             -- 'domestic' | 'overseas'
  content TEXT,
  fetched_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_drug_source (drug_id, source),
  FOREIGN KEY (drug_id) REFERENCES drugs(id)
);
```

## 4. 외부 API 연동 명세

> ⚠️ 아래 요청주소/오퍼레이션명은 검색 시점 기준 확인된 정보입니다. 공공데이터포털 API는 가끔 버전이 올라갑니다(예: `...Service01` → `...Service02`). 실제 개발 착수 전 [data.go.kr](https://www.data.go.kr)에서 활용신청 후 최신 명세를 한 번 더 확인하세요.

### 4.1 의약품 낱알식별정보 (국내, 모양·색깔 검색용 — REQ-F-004, REQ-F-005)
- 요청주소: `http://apis.data.go.kr/1471000/MdcinGrnIdntfcInfoService01/getMdcinGrnIdntfcInfoList01`
- 주요 파라미터: `serviceKey`, `item_name`(약 이름), `pageNo`, `numOfRows`, `type=json`
- 응답에 낱알 이미지 URL, 모양, 색깔, 각인 정보 포함

### 4.2 의약품개요정보 e약은요 (국내, 상세/부작용 — REQ-F-006, REQ-F-007)
- 요청주소: `http://apis.data.go.kr/1471000/DrbEasyDrugInfoService/getDrbEasyDrugList`
- 주요 파라미터: `serviceKey`, `itemName`(약 이름), `entpName`(업체명, 선택), `pageNo`, `numOfRows`, `type=json`
- 응답에 효능(문항1), 사용법(문항2), 주의사항(문항3·4), 상호작용(문항5), 부작용(문항6) 포함 → `drugs` 테이블과 `side_effect_cache(source='domestic')`에 매핑

### 4.3 DUR품목정보서비스 — 병용금기 (REQ-F-009 확장)
- 요청주소: `http://apis.data.go.kr/1471000/DURPrdlstInfoService03/getUsjntTabooInfoList03`
- 주요 파라미터: `serviceKey`, `itemName` 또는 `itemSeq`, `type=json`
- 응답의 병용금기 조합을 `dur_pairs` 테이블에 저장/캐싱
- **기존 기능**: 즐겨찾기한 약들 사이에 병용금기 조합이 있는지 자동 체크
- **추가 기능**: 약 상세 화면에서 현재 약의 `itemSeq`(= `drugs.id`) 또는 제품명을 기준으로 DUR 정보를 조회하여 **“함께 먹으면 안 되는 약”** 탭에 표시
- 상세 화면 결과에는 최소한 `상대 약품명`, `상대 품목기준코드(가능한 경우)`, `금기/주의 구분`, `사유`를 포함
- 동일한 상대 약이 중복 반환되면 프론트에 전달하기 전에 중복 제거
- 조회 결과가 없으면 오류로 처리하지 말고 `items: []`와 함께 사용자 안내 문구를 반환
- DUR 외부 API 장애/타임아웃 시 화면 전체를 실패시키지 말고 해당 탭에서만 `현재 병용금기 정보를 불러올 수 없습니다`를 표시

### 4.4 openFDA drug/event — 해외 부작용 사례 (REQ-F-008)
- 요청주소: `https://api.fda.gov/drug/event.json`
- 인증키 불필요(무료, 키 없이 분당 40회 / 무료 키 발급 시 분당 240회)
- 쿼리 예시: `?search=patient.drug.medicinalproduct:"ACETAMINOPHEN"&limit=5`
- **매핑 이슈**: 국내 API는 한글 제품명, openFDA는 영문 성분명 기준 검색입니다. `drugs.ingredient_en` 컬럼(e약은요 응답의 영문 주성분명, 없으면 수동 매핑 테이블)을 검색어로 사용하세요. 매핑 실패 시 `available:false` + 안내 메시지 반환 (REQ-N-004).

### 4.5 어댑터 구현 공통 규칙 (REQ-N-001, REQ-N-003)
- 모든 외부 API 호출은 `adapter` 계층(예: `EyakClient`, `GranuleClient`, `DurClient`, `OpenFdaClient`)에서만 수행하고, Service/Controller는 어댑터를 통해서만 접근
- 호출 전 `side_effect_cache`(24시간 이내 데이터)를 먼저 확인 → 있으면 즉시 반환
- 외부 API 타임아웃은 3초로 설정, 타임아웃/5xx 발생 시 예외를 던지지 말고 `{available:false, message:"현재 정보를 불러올 수 없습니다"}` 형태로 정상 응답
- 재시도는 최대 1회(exponential backoff 불필요, 짧은 프로젝트 특성상 단순 재시도로 충분)

### 6.1 SCR-DETAIL-001 상세 화면 UI/UX 규칙 — 반드시 반영

약 상세 화면은 **모든 상세 내용을 한 화면에 동시에 펼쳐 놓지 말고 탭 방식으로 구성**하세요. 상단에는 약 이름, 대표 이미지, 제조사/성분 등 최소 기본 요약과 즐겨찾기 하트 버튼만 유지하고, 상세 내용은 아래 탭에서 전환합니다.

탭 순서:
1. `기본정보` — 제품명, 제조사, 모양, 색깔, 식별표시, 주성분 등
2. `효능·복용정보` — 효능·효과, 용법·용량, 사용상의 주의사항
3. `부작용` — 국내(e약은요) / 해외(openFDA) 부작용을 구분해서 표시
4. `함께 먹으면 안 되는 약` — DUR 기반 병용금기/주의 의약품 목록

동작 규칙:
- 최초 진입 시 `기본정보` 탭을 선택
- **선택된 탭의 내용만 렌더링/표시**하고, 다른 탭 내용은 같은 화면 아래에 이어 붙이지 않음
- 즐겨찾기는 탭으로 만들지 말고 약 이름 옆 또는 상단 우측의 `♡/♥` 버튼으로 제공
- `함께 먹으면 안 되는 약` 탭을 처음 눌렀을 때 DUR 조회를 실행하는 **lazy loading**을 우선 적용하여 초기 상세화면 로딩을 가볍게 유지
- DUR 항목은 `약 이름`, `금기/주의 배지`, `병용 사유`를 한 카드/행에서 쉽게 확인할 수 있게 구성
- `금기`는 위험 정보이므로 빨간색 계열 포인트를 사용하되 화면 전체를 빨갛게 만들지 않음. `주의`는 주황/노랑 계열 보조색 사용
- DUR 결과가 3개를 초과하면 처음에는 일부만 보여주고 `전체 보기` 또는 펼치기 UI를 사용할 수 있음
- 데이터 없음: `확인된 병용금기 정보가 없습니다`
- API 실패: `현재 병용금기 정보를 불러올 수 없습니다` + 재시도 버튼

디자인 규칙:
- 메인 테마색은 **`#73CBF1`**
- 전체 분위기는 **귀엽지만 유치하지 않고, 깔끔한 의료 정보 서비스** 스타일
- 배경은 흰색 또는 아주 옅은 하늘색, 카드에는 넉넉한 여백과 둥근 모서리 사용
- `#73CBF1`은 선택 탭 밑줄/배경, 주요 버튼, 아이콘 포인트에 사용하고 모든 영역을 진한 파란색으로 채우지 않음
- 카드/버튼은 둥근 형태(대략 12~20px radius), 그림자는 매우 약하게 사용
- 의료 정보의 가독성이 우선이며 과도한 캐릭터, 일러스트, 장식은 사용하지 않음
- 모바일에서는 탭이 한 줄에 들어가지 않으면 가로 스크롤 가능하게 처리하고, 선택 상태가 명확해야 함

> **중요:** 기존 `01_요구사항정의서_화면설계서_추적성매트릭스.docx` 또는 `03_API명세서.yaml`에서 상세 화면 DUR 조회가 정의되어 있지 않더라도, **이 문서의 수정된 상세화면/DUR 규칙을 최신 요구사항으로 우선 적용**하세요.

핵심 엔드포인트: `POST /api/auth/signup`, `POST /api/auth/login`, `GET /api/drugs/search`, `GET /api/drugs/{id}`, `GET /api/drugs/{id}/side-effects`, **`GET /api/drugs/{id}/contraindications`**, `GET|POST /api/favorites`, `DELETE /api/favorites/{id}`, `GET /api/dashboard/summary`

### 7.1 상세 화면 병용금기 조회 API — 신규 추가

기존 `03_API명세서.yaml`에는 아래 엔드포인트가 없으므로 구현 시 함께 추가하고 Swagger에도 노출하세요.

`GET /api/drugs/{drugId}/contraindications`

응답 예시:
```json
{
  "drugId": "12345678",
  "available": true,
  "items": [
    {
      "drugId": "87654321",
      "name": "OO정",
      "manufacturer": "OO제약",
      "type": "CONTRAINDICATED",
      "reason": "병용 시 부작용 위험이 증가할 수 있습니다."
    }
  ],
  "message": null
}
```

규칙:
- `type`: `CONTRAINDICATED`(금기) 또는 `CAUTION`(주의)
- 상대 약의 제조사 정보가 DUR 응답에 없으면 `manufacturer`는 `null` 허용
- 결과 없음: `available: true`, `items: []`, `message: "확인된 병용금기 정보가 없습니다"`
- DUR API 장애/타임아웃: `available: false`, `items: []`, `message: "현재 병용금기 정보를 불러올 수 없습니다"`
- HTTP 200으로 부분 실패 상태를 표현하여 상세 페이지의 다른 탭이 정상 동작하도록 함

```
    adapter/        # EyakClient, GranuleClient, DurClient, OpenFdaClient (외부 API 전담)
    repository/      # Spring Data JPA Repository
    entity/          # User, Drug, Favorite, DurPair, SideEffectCache
    dto/
    config/          # SecurityConfig(JWT), WebClientConfig, SwaggerConfig
    exception/       # GlobalExceptionHandler

frontend/
  src/
    views/           # LoginView, SignupView, SearchView, DrugDetailView, FavoritesView, DashboardView
    components/      # DrugCard, DrugDetailTabs, SideEffectPanel, ContraindicationPanel, DurWarningBanner 등
    stores/          # auth.js (Pinia), favorites.js
    api/             # axios 인스턴스 + 엔드포인트 함수
    router/          # index.js (가드 포함)
```

레이어 원칙: Controller는 요청/응답 변환만, 비즈니스 로직(캐싱 판단, DUR 매칭 등)은 Service, 외부 API 호출은 반드시 Adapter를 거칩니다.
